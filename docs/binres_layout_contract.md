# GUIX `.bin` (binres) layout contract (target)

This document records the **byte layout + alignment/endianness rules** we target for GUIX binary resource files generated by `tools/guix_studio_cli`.

It’s intentionally focused on what the **loader expects**, and what **GUIX Studio writes**.

## References

- Loader (theme binres): `common/src/gx_binres_theme_load.c`
- Loader (standalone pixelmap binres): `common/src/gx_binres_pixelmap_load.c`
- Studio writer: `guix_studio/binary_resource_gen.cpp`

## Endianness

- Default output is little-endian.
- If `--big_endian` is set:
  - All serialized integer header fields are big-endian.
  - Pixelmap payload word-swapping follows Studio’s behavior (format-dependent). For 32bpp formats, Studio writes payload as big-endian 32-bit words.
  - String bytes remain byte-wise (NUL-terminated, and string length fields are swapped as integers).

## Theme binres (`GX_RESOURCE_HEADER` + theme(s) + string tables)

### High-level layout

When the resource header is included (default):

- `GX_RESOURCE_HEADER` (20 bytes)
- Theme data block (size = `theme_data_size` from resource header)
- String data block (size = `string_data_size` from resource header)

When `--no_res_header` is used:

- Theme data block (no leading resource header)
- String data block

### `GX_RESOURCE_HEADER` (20 bytes)

Fields (in order):

- `USHORT magic` (0x4758)
- `USHORT version`
- `USHORT theme_count`
- `USHORT language_count`
- `ULONG theme_data_size`
- `ULONG string_data_size`
- `ULONG total_data_size`

### Per-theme layout

Each theme is serialized as:

- `GX_THEME_HEADER` (114 bytes)
- Optional color section (`GX_COLOR_HEADER` + table)
- Optional palette section (not implemented in CLI yet)
- Optional font section (`GX_FONT_HEADER` entries + optional font payload)
- Optional pixelmap section (`GX_PIXELMAP_HEADER` entries + optional pixelmap payload)

The theme header contains **counts** and **section data sizes**. Loader code uses these sizes to advance offsets and locate sections.

### Pixelmap section alignment/padding

From Studio and loader behavior:

- Studio computes padding per pixelmap so that the **pixelmap data output position** (immediately after header) is aligned.
- For modern projects (`GX_VERSION_BINRES_DATA_ALIGNMENT_FIX`), Studio aligns pixelmap data to a 32-bit boundary.
- Loader aligns read offsets to 32-bit boundaries when reading pixelmap data.

Practical rule we target for now:

- For pixelmap payloads embedded after the pixelmap header, pad with `0x00` so that the payload begins on a 4-byte boundary.

### `GX_PIXELMAP_HEADER`

Fields (in order), as read by the theme loader:

- `USHORT magic`
- `USHORT index`
- `GX_UBYTE version_major`
- `GX_UBYTE version_minor`
- `GX_UBYTE flags`
- `GX_UBYTE format`
- `ULONG map_size`
- `ULONG aux_data_size`
- `ULONG transparent_color`
- `USHORT width`
- `USHORT height`
- `ULONG data_size`
- `ULONG data_offset` *(present in newer versions)*

Loader notes:

- If `data_offset != 0`, the loader seeks to that absolute offset and re-reads the header before reading payload.
- If `data_offset == 0`, payload is expected to follow the header (with alignment/padding).

## Standalone pixelmap binres

Standalone pixelmap binres files are loaded by `gx_binres_pixelmap_load` and have a different outer header:

- `USHORT type` (must be `GX_RESOURCE_TYPE_BINRES_STANDALONE`)
- `USHORT version` (unused by the seek routine)
- `ULONG count`
- Optional offset table (`ULONG[count]`) if `count > 1`
- Resource payload(s)

This is the format used by `tutorials/demo_guix_binres_standalone/pixelmap_red_apple.bin`.

## Current CLI status (this branch)

- `--big_endian` is honored for header integer serialization in theme binres.
- Theme binres generation includes:
  - Theme header + colors
  - Font headers (default/system fonts only)
  - Pixelmap headers
  - String tables
- Pixelmap payloads:
 - Pixelmap payloads:
  - Phase-3 embeds a real uncompressed 32ARGB map for eligible file-backed embedded pixelmaps:
    - PNG decode at generation time → `GX_COLOR_FORMAT_32ARGB` payload (`A<<24 | R<<16 | G<<8 | B`)
    - `map_size == data_size == width * height * 4`
    - payload begins on a 4-byte boundary
  - Cross-theme dedup (Studio-style): when a pixelmap payload was already emitted earlier in the file,
    later themes may emit a header-only entry with non-zero `data_offset` pointing at the referenced
    `GX_PIXELMAP_HEADER` (loader re-reads header + payload from the referenced location).
